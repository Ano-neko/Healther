# 记忆系统

目标：一条永不“新建对话”的长期陪伴式对话，聊得再久，Agent 也记得 **你是谁** 和 **它是来干什么的**。

核心原则：**上下文 ≠ 记忆**。身份和你的实时状态不放在对话历史里，而是在每次调用模型时从数据库重新组装，所以历史怎么被压缩都丢不掉。

## 五层结构

| 层 | 内容 | 何时进入上下文 | 由谁更新 | 存储 |
|---|---|---|---|---|
| **L0 身份** | 人设、职责、饮食记录流程、记忆规则、边界 | 每次，最前面 | 代码（`Persona.swift`） | — |
| **L1 档案** | 称呼、身高、健康状况、目标、饮食偏好、作息、性格……（≈1–2k tokens） | 每次 | Agent 的 `update_profile`、记忆整理 | `profile` |
| **L2 此刻** | 当前时间、昨晚睡眠、今日活动/饮食/饮水/情绪、待确认草稿、目标、自动检索到的相关记忆 | 每轮重新生成，插在本轮用户消息之前 | 自动 | Apple 健康 + 本地表 |
| **L3 长期记忆** | 一条一件事：事件、情绪、偏好细节、规律、约定 | 自动检索的前几条进入 L2；其余用 `recall` 主动查 | `remember` / `forget`、记忆整理、每日复盘 | `memories` + FTS |
| **日记** | 每天一篇，概括 TA 的一天和情绪 | 最近 5 天进入稳定前缀 | 每日复盘 | `episodes` |
| **L4 对话** | 未压缩的近期原文 + 更早对话的滚动摘要（前情提要） | 每次 | 自动压缩 | `messages` + `kv` |

## 每次请求的结构

```
[system]  L0 人设 + L1 档案 + 最近日记 + 前情提要     ← 稳定，命中前缀缓存
[user / assistant / tool …]  未压缩的历史（L4）
[system]  「此刻」L2 实时状态 + 自动检索的 L3 记忆   ← 每轮更新
[user]    本轮消息（含照片）
[assistant / tool …]  本轮的工具调用过程
```

动态内容放在靠后的位置，是为了让前面的大段内容在多轮之间字节不变，从而命中 DeepSeek 的前缀缓存（实测命中率 80% 以上），降低成本和延迟。

## 压缩（Compaction）

每轮结束后检查：未压缩历史估算超过 `compactThresholdTokens`（默认 24k）时，保留最近约 10k tokens 的原文（从一条用户消息开始切），把更早的部分交给工具模型：

- 和已有的前情提要合并，重写成一段 ≤600 字的摘要；
- 提取值得长期保存的记忆（与已有记忆冲突时用 `replaces` 取代）；
- 必要时更新档案。

被压缩的消息仍保存在数据库里（用于 App 显示历史和每日复盘），只是不再进入上下文。

## 每日复盘（Reflection）

每轮结束后，为“已经过去、还没写日记的日子”生成日记：当天对话 + 饮食合计 + 健康数据 + 情绪记录 → 120–250 字的日记、一句状态概括、值得以后提起的点，以及新的长期记忆。

## 检索

SQLite FTS5 的 `unicode61` 分词器不会切分中文，所以我们自己做分词：中文连续字符拆成单字 + 双字（bigram），英文/数字按词。排序：

```
score = (bm25 相关度 + 4 × 关键词覆盖率) × (0.7 + 0.15 × 重要性) × 时间衰减(0.5 + 0.5·e^(−天数/45))
```

之后可以接入 Apple `NaturalLanguage` 的端侧句向量做语义检索，无需额外的 API。

## 记忆卫生

- **取代而不是修改**：信息变化时新记忆取代旧记忆（`superseded_by`），旧记忆不再参与检索，但留档可查。
- **去重**：与现有记忆双向高度重合的新记忆会被合并。
- **不记数字**：健康数据本身就在 Apple 健康里，记忆只记“意义”和“来龙去脉”。
- **不猜性别**：档案里没有性别时，摘要和日记一律用称呼或“TA”。
- **用户可控**：App 中可以查看和删除任何档案项与记忆（`erase` 为物理删除）。
